# یادآوری قابل‌تنظیم

یادآوری شخصی است: هر عضو فعلی پروژه، از جمله بیننده، برای خودش روی تسک
یادآوری می‌سازد. سایر اعضا و مدیر پروژه یادآوری او را در این API نمی‌بینند و
نمی‌توانند آن را تغییر دهند. شناسهٔ گیرنده از هویت تأییدشده می‌آید و در JSON
درخواست قابل تعیین نیست.

## مسیرهای API

نشانی پایه:

```text
/projects/{projectID}/tasks/{taskID}/reminders
```

| متد | مسیر | کاربرد |
| --- | --- | --- |
| POST | نشانی پایه | ساخت یادآوری |
| GET | نشانی پایه با `?limit=20&cursor=…` | فهرست شخصی با صفحه‌بندی |
| POST | `/{reminderID}/snooze` | تعویق یا تعیین زمان تازه |
| DELETE | `/{reminderID}` | لغو یادآوری |

همهٔ درخواست‌ها هدرهای معمول `X-APIKEY`، `USER-ID` و `APP-ID` را می‌خواهند.

### زمان مشخص

```http
POST /projects/{projectID}/tasks/{taskID}/reminders
Content-Type: application/json

{
  "remindAt": "2026-10-25T09:00:00+03:30",
  "note": "نسخهٔ نهایی را پیگیری کن"
}
```

### فاصله از موعد تسک

```json
{
  "minutesBeforeDue": 1440,
  "note": "یک روز پیش از موعد، خروجی را بررسی کن"
}
```

یکی از `remindAt` و `minutesBeforeDue` لازم است؛ هر دو با هم پذیرفته نمی‌شوند.
برای نمونه، `60` یعنی یک ساعت قبل، `1440` یک روز قبل و `0` خود موعد.
فاصله از صفر تا ۴۳۲۰۰ دقیقه، معادل ۳۰ روز است. تسک باید موعد داشته باشد و
زمان محاسبه‌شده هنگام ساخت در آینده باشد. ساخت روی تسک تکمیل‌شده مجاز نیست.
یادداشت اختیاری و حداکثر ۱۰۰۰ نویسه است.

برای چند یادآوری، چند درخواست مستقل بفرستید؛ حداکثر ۱۰ یادآوری با وضعیت
`scheduled` برای هر کاربر روی هر تسک مجاز است. یادآوری‌های ارسال‌شده یا
لغوشده این ظرفیت را مصرف نمی‌کنند. ساعت درخواست RFC3339 با منطقهٔ زمانی است؛
ذخیره‌سازی و پاسخ‌ها UTC هستند.

پاسخ `201` شامل این فیلدها است:

```json
{
  "id": "<reminder-uuid>",
  "projectId": "<project-uuid>",
  "taskId": "<task-uuid>",
  "remindAt": null,
  "minutesBeforeDue": 1440,
  "scheduledFor": "2026-10-25T05:30:00Z",
  "note": "یک روز پیش از موعد، خروجی را بررسی کن",
  "status": "scheduled",
  "sentAt": null,
  "createdAt": "2026-10-21T12:00:00Z",
  "updatedAt": "2026-10-21T12:00:00Z"
}
```

`scheduledFor` زمان محاسبه‌شده است. برای یادآوری نسبیِ ارسال‌نشده، این زمان با
تغییر موعد تغییر می‌کند. حذف موعد آن را `null` می‌کند و یادآوری منتظر موعد
تازه می‌ماند. در یادآوری ارسال‌شده، زمان همان نوبت ارسال حفظ می‌شود و تغییر
موعد به‌تنهایی اعلان دیگری تولید نمی‌کند.

### تعویق

```http
POST /projects/{projectID}/tasks/{taskID}/reminders/{reminderID}/snooze
Content-Type: application/json

{"remindAt":"2026-10-25T10:00:00+03:30"}
```

پاسخ `200` و رکورد به‌روز است. یادآوریِ `scheduled` یا `sent` به یک زمان
مشخصِ آینده منتقل می‌شود. حالت نسبی قبلی کنار می‌رود، وضعیت دوباره `scheduled`
می‌شود و نوبت ارسال تازه‌ای می‌گیرد. یادآوری `cancelled` قابل تعویق نیست؛
برای آن یادآوری جدید بسازید. فعال‌کردن دوبارهٔ یادآوری ارسال‌شده نیز سقف ۱۰
یادآوری فعال را رعایت می‌کند.

### لغو و فهرست

`DELETE` پاسخ `204` دارد و وضعیت را `cancelled` می‌کند. درخواست تکراری برای
لغو همان یادآوری نیز `204` است. مالک حتی پس از خروج از پروژه یا آرشیو تسک
می‌تواند یادآوری خودش را لغو کند؛ خواندن و تغییر زمان به عضویت فعلی و پروژه و
تسک فعال نیاز دارد.

فهرست، جدیدترین رکوردها را ابتدا در قالب `{"items":[…],"nextCursor":"…"}`
برمی‌گرداند. `limit` بین ۱ تا ۱۰۰ است. مقدار `nextCursor` را بدون تغییر برای
صفحهٔ بعد بفرستید؛ آخرین صفحه `null` دارد. فهرست شامل وضعیت‌های `scheduled`،
`sent` و `cancelled` است و فقط رکوردهای خود کاربر را نشان می‌دهد.

خطای ورودی `400`، نبود هویت `401`، نبود منبع یا یادآوری در محدودهٔ کاربر `404`
و رسیدن به سقف، تعویق یادآوری لغوشده یا ساخت روی تسک تکمیل‌شده `409` است.

## ارسال، تلاش مجدد و محدودیت‌ها

- Worker در شروع API و سپس هر ۳۰ ثانیه اجرا می‌شود و هر بار حداکثر ۱۰۰ یادآوری
  آماده را پردازش می‌کند. بنابراین زمان ارسال تقریبی است و با بار صف و سرعت
  سرویس اعلان می‌تواند دیرتر از زمان انتخاب‌شده باشد.
- تسک تکمیل‌شده یا آرشیوشده، پروژهٔ آرشیوشده و کاربری که دیگر عضو پروژه نیست
  اعلان نمی‌گیرند. یادآوری تا بازشدن تسک، بازیابی پروژه یا عضویت مجدد منتظر
  می‌ماند. اگر زمانش گذشته باشد، پس از فعال‌شدن شرایط ارسال می‌شود؛ خودکار
  منقضی یا پاک نمی‌شود. برای جلوگیری از آن، مالک می‌تواند لغوش کند.
- اعلان با نوع `task.reminder` به سرویس `NOTIFICATION_SERVICE_URL` می‌رود.
  عنوان فعلی تسک و یادداشت شخصی در بدنه‌اند؛ یادآوری برای خود کاربر است و
  actor ندارد تا به‌عنوان اعلانِ تغییرِ خود کاربر حذف نشود.
- وقتی `NOTIFICATION_SERVICE_URL` تنظیم نیست، worker شروع نمی‌شود و
  یادآوری‌ها در دیتابیس باقی می‌مانند. پس از تنظیم و راه‌اندازی دوبارهٔ API،
  نوبت‌های آماده پردازش می‌شوند.
- پس از پاسخ موفق HTTP از سرویس اعلان، وضعیت `sent` ثبت می‌شود. خطا باعث
  مصرف‌شدن یادآوری نمی‌شود؛ تلاش مجدد از یک دقیقه شروع می‌شود و تا سقف یک
  ساعت بین تلاش‌ها افزایش می‌یابد. کاربر همچنان می‌تواند لغو یا تعویق دهد.
- یک قفل دیتابیس از ارسال هم‌زمان توسط دو نمونهٔ API جلوگیری می‌کند. قفل فقط
  هنگام یک درخواست با مهلت پنج ثانیه نگه داشته می‌شود. لغو و تعویق منتظر ارسال
  در حال انجام می‌مانند؛ اعلانی که پیش‌تر وارد مرحلهٔ ارسال شده ممکن است برسد.
- کلید `Idempotency-Key` در تلاش‌های یک نوبت ثابت است. اگر سرویس اعلان موفق
  شود ولی ارتباط یا commit قطع شود، تلاش بعدی همان کلید را می‌فرستد. جلوگیری
  کامل از اعلان تکراری به پشتیبانی سرویس اعلان از این کلید وابسته است؛ ادعای
  ارسال دقیقاً یک‌بار بدون آن نداریم. تعویق، کلید نوبت تازه می‌سازد.

این قابلیت یادآوری یک‌باره است؛ تکرار روزانه، کانال جدید ایمیل/پیامک و تنظیم
یادآوری برای شخص دیگر جزو این API نیست. زمان‌بندی روی سرور انجام می‌شود و باز
بودن مرورگر کاربر لازم نیست.

## مسیر کد و نصب

- `internal/task/reminder.go`: قواعد زمان، موعد، مالکیت و پاسخ‌های سرویس.
- `internal/task/repository_reminder.go`: ذخیره، سقف تعداد و تغییرهای شخصی.
- `internal/task/reminder_worker.go`: انتخاب نوبت‌های آماده و ثبت نتیجهٔ واقعی
  ارسال. از صف موقت dispatcher برای این مسیر استفاده نمی‌شود.
- `internal/task/handler_reminder.go`: مسیرهای HTTP و بررسی JSON.
- `internal/notification/client.go`: ارسال همگام با کلید ثابت برای تلاش مجدد.

Migration شمارهٔ ۲۳ را با روش معمول پروژه اعمال و API را بازسازی کنید:

```sh
docker compose run --rm migrate
docker compose up --build -d api
```

آزمون‌ها:

```sh
go test ./internal/task ./internal/notification
TASKMANAGER_TEST_DATABASE_URL='postgres://taskmanager:taskmanager@localhost:5432/taskmanager_test?sslmode=disable' go test ./internal/task -run 'Test.*Reminder' -v
```

آزمون‌های دیتابیس، جداسازی کاربران، صفحه‌بندی، تعویق، تلاش مجدد، کلید پایدار،
شرایط توقف ارسال، سقف هم‌زمان و چند worker را در schema موقت بررسی می‌کنند.
بدون متغیر دیتابیس آزمایشی skip می‌شوند؛ هرگز دیتابیس عملیاتی را برای آزمون
استفاده نکنید.
