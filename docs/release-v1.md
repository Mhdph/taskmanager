# وضعیت آمادگی نسخهٔ ۱

تاریخ بررسی: ۲۰۲۶-۱۰-۲۳. بررسی شامل مخزن API و فرانت مستقل در پوشهٔ همسایهٔ `ui` است.

## تغییرات انجام‌شده

- ورود سازگار با NUP Admin: دریافت `?tt=`، تبادل یک‌باره از طریق
  `POST /auth/bridge` و `nupConfirmBridgeToken`، حذف توکن از URL، و نشست با
  کوکی‌های `token`، `app-id`، `id` و `from-support-menu`.
- ارسال هدرهای هویت در REST، آپلود تسک و آپلود چت؛ قبول `yes/no` برای حالت
  پشتیبانی پس از تأیید هویت در سرویس اصلی.
- حذف هویت پیش‌فرض توسعه از فرانت production؛ صفحه‌های ورود و ثبت‌نام محلی
  محدود به دمو؛ پاک‌شدن کوکی‌های نشست و کش درخواست‌ها هنگام خروج.
- جلوگیری از فعال‌شدن `IDENTITY_DEV_MODE` خارج از محیط development/test.
- رفع برخورد کلید کش هویت برای شناسه‌های دارای `:`، محدودکردن کش به ۴۰۹۶
  رکورد و جلوگیری از رقابت حذف رکورد منقضی با ثبت رکورد جدید.
- جلوگیری از انتقال هدرهای حساس به مقصد redirect سرویس هویت و محدودکردن
  حجم پاسخ‌های آن به یک مگابایت.
- رفع HTML injection در نام و توضیح تیم، برچسب‌ها و خطاهای فرم؛ محدودکردن
  رنگ‌های دریافتی API به مقدار hex معتبر پیش از استفاده در CSS.
- جلوگیری از کش پاسخ‌های خصوصی در API و پروکسی؛ افزودن `nosniff` و سیاست
  جلوگیری از ارسال referrer؛ سقف ۲۶ مگابایت برای بدنهٔ پروکسی، حتی بدون
  `Content-Length`، با پاسخ ۴۱۳ برای درخواست بزرگ‌تر.
- افزودن CI بک‌اند با PostgreSQL جداگانه و race detector، و محدودکردن دسترسی
  workflowها به خواندن مخزن.

## بررسی‌های موفق محلی

- فرانت: ۴۷ تست، TypeScript، ESLint، Prettier و بیلد production.
- بک‌اند: `go test -race ./...`، `go vet ./...` و `go build ./...`؛ تست‌های
  وابسته به سرویس‌های خارجی بدون تنظیم متغیرهای تست skip شده‌اند.
- تست‌های بازگشتی برای bridge، هدرهای پشتیبانی، شکست ورود، خروج از نشست،
  نبود fallback ادمین در production، XSS، کش هویت و محدودیت حجم درخواست.
- اجرای واقعی بیلد Node و بررسی مرورگری صفحهٔ بدون نشست: درخواست ورود از
  پنل اصلی نمایش داده می‌شود و فضای کاری نمونه در production نمایش داده نمی‌شود.

## موارد لازم پیش از تأیید نهایی ریلیز

1. اجرای تست‌های PostgreSQL و MinIO در محیط تست. این ماشین PostgreSQL قابل
   دسترس ندارد و Docker به دسترسی مدیریتی نیاز دارد؛ CI جدید نیز هنوز روی
   سرویس گیت اجرا نشده است. برای PostgreSQL از دیتابیس اختصاصی تست استفاده کنید:

   ```sh
   TASKMANAGER_TEST_DATABASE_URL='postgres://USER:PASS@HOST:5432/TEST_DB?sslmode=disable' go test -race -count=1 ./...
   ```

   تست واقعی ذخیره‌سازی به `TASKMANAGER_TEST_MINIO_ENDPOINT` و متغیرهای
   access key، secret key و bucket معرفی‌شده در تست‌های storagegc نیاز دارد.

2. آزمون ورود با لینک واقعی پنل و endpoint واقعی هویت، شامل کاربر عادی، ادمین،
   حالت پشتیبانی، توکن منقضی و جداسازی دو tenant. قرارداد با کد NUP مقایسه و
   با سرویس شبیه‌سازی‌شده تست شده؛ سرویس واقعی در این بررسی آزمایش نشده است.
3. اجرای بررسی آسیب‌پذیری وابستگی‌ها با شبکهٔ سالم. `npm audit` به‌دلیل خطای
   DNS/timeout کامل نشد؛ پایگاه آسیب‌پذیری‌های Go نیز بررسی آنلاین نشده است.
4. روی staging همهٔ migrationها تا ۲۴، دریافت فایل با URL عمومی MinIO،
   TLS، پشتیبان‌گیری و بازیابی داده را تأیید کنید. Compose موجود تنظیمات محلی
   و گذرواژه‌های نمونه دارد. محیط انتشار باید `APP_ENV=production` و
   `IDENTITY_DEV_MODE=false` داشته باشد.

طبق README فرانت، دعوت‌ها، اعلان‌های صفحهٔ نمونه، رویدادهای تقویم، فاکتورها و
آپلودهای نمونهٔ صفحهٔ فایل‌ها هنوز قابلیت نمایشی‌اند؛ قابلیت‌های واقعی چت و
تسک قرارداد API جداگانه دارند. دامنهٔ نسخهٔ ۱ باید این تفاوت را روشن کند.

تغییرات در فایل‌های محلی آمادهٔ بازبینی هستند؛ انتشار، push یا ساخت tag انجام نشده است.
